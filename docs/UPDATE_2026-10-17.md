# TRAILS: update of 17 October

**Repo:** https://github.com/LexaPankov/trails (public)
**Live demo:** https://lexapankov.github.io/trails/ (HTTPS, works on phones, rebuilt on every push to `main`)
**Deadline:** 18 October

## In one paragraph

The AMD requirement is now met: every AI story in TRAILS is written by **Gemma 4 31B running on AMD GPUs**
(AMD Developer Cloud Token Factory), and the app shows that on the story card. The project moved to the
repo root, got a public site, nearly twice as many places (269 → 465), five more camera landmarks
including the Colosseum and Pantheon (22 → 27), a "use my current location" button, and a one-click
start on Windows. Tests: 39/39 unit tests, and the end-to-end browser test passes on desktop and mobile
sizes, including against the live site.

## What is new

### 1. AI storyteller on AMD (the hackathon requirement)
- Gemma 4 31B (`Gemma-4-31B-IT`) on the AMD Developer Cloud Token Factory, through its OpenAI-compatible API.
- Measured with `npm run story:eval` on 5 fixed walks: **5/5 succeeded, 17/17 stops covered, no numbers
  outside our source facts**, 9–50 s per story (`docs/story_eval_Gemma-4-31B-IT.json`).
- The story card says which model and provider wrote it: "Written by Gemma-4-31B-IT · Gemma 4 31B on AMD
  Developer Cloud Token Factory (AMD GPUs)".
- **Public site without a key:** the 4 preset walks have stories Gemma wrote ahead of time
  (`public/data/story_cache.json`, badge says "pre-generated"). Other walks on the public site get the
  offline story from our notes. Live stories for any walk: run the app locally (see "Run it").
- Fixes found while running it for real: the app gave up after 45–50 s although Gemma sometimes needs
  ~50 s (now 100 s, and the button says "up to a minute"); Gemma also wrote citations like `[1]` into the
  text, so they showed twice (now moved into the citation list).
- Optional `STORY_JSON_MODE=1` asks the model for strict JSON.
- The key is never in the repo or the browser build: the server reads it from `.env.local` (git-ignored).

### 2. Public website
- GitHub Actions (`.github/workflows/pages.yml`) runs the tests, builds and publishes to GitHub Pages
  on every push to `main`. Map tiles on the public site: OpenStreetMap (no key).
- On a static host the story card now explains in plain words that the live storyteller is not
  reachable, instead of "story server answered 501" (patch from our teammate, merged), and the story
  server can allow other sites to call it (`STORY_ALLOW_ORIGIN`).

### 3. Bigger dataset: 465 places (74 hand-curated + 391 imported, was 195)
- Places with no build date in Wikidata are now dated from an "ancient only" Wikidata type (Roman
  temple, thermae...) or from the Wikipedia description ("17th-century Baroque church"). Each record
  says where its period came from (`period_source`).
- Little-known sites that Wikipedia describes in the past tense ("was a temple") are skipped. Without
  this rule the "Ancient stones" preset sent people to the Villa Publica, which no longer exists.
- Fewer real places lost as "duplicates" (15 m between imports instead of 30 m), so for example the
  Fontana dell'Acqua Paola and San Giuseppe dei Falegnami stay.
- Photos for new places, compressed on import (98 MB → 28 MB). Validator passes.

### 4. Camera: 27 landmarks (was 22)
- Added the **Colosseum, Pantheon, Arch of Constantine, Trajan's Column and Four Rivers Fountain**,
  using freely licensed Wikimedia Commons photos; every photo was checked by eye (about half rejected).
  New script: `scripts/fetch_commons_landmarks.py`.
- Re-measured on 120 held-out photos: right landmark ranked first 82.5 %, confidently recognised 60.8 %,
  confidently wrong 1.7 % (2 photos: Trajan's Column mistaken for the Column of Marcus Aurelius or
  Sant'Agnese). Colosseum 7/7, Arch of Constantine 5/5, Pantheon 7/9 ranked first.

### 5. "Use my current location"
- The **From** field has a "Use my current location" button: one GPS fix, labelled with the nearest street.
- Outside Rome it says how far away you are and suggests a map pin or Demo mode, instead of planning a
  500 km walk. Refused permission, timeout and missing HTTPS each get a clear message.
- Tested with an emulated phone GPS (Rome, Milan, permission refused), also on the live site.

### 6. Easier to run, especially on Windows
- **`start-trails.cmd`**: double-click it. Installs dependencies on first run, builds, starts the app
  with the AI storyteller and opens http://localhost:8787.
- PowerShell blocks `npm` by default on Windows ("running scripts is disabled"): use `npm.cmd`, or run
  `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` once.
- The Python data scripts mis-read files on Windows (no UTF-8), which would have mangled the Italian
  names in `places.json`. Fixed in all of them.

### 7. Smaller things
- The camera library (MediaPipe) now loads only when the camera opens.
- Removed an unused package (`onnxruntime-web`).
- README: "Try it in 2 minutes" for judges at the top, setup for the AMD storyteller.
- `docs/REPORT.md` and the screenshots updated to what was actually run (the old story screenshot showed
  a fake test model, and the old route screenshot had no map).
- AMD Instinct scripts kept as an alternative: `amd/serve_llm.sh` (vLLM on ROCm), `amd/train_rocm.sh`
  (train the preference model on an AMD GPU), steps in `docs/AMD_RUNBOOK.md`.

## Run it

```
git clone https://github.com/LexaPankov/trails.git
cd trails
```

Windows: double-click `start-trails.cmd`. Elsewhere: `npm install`, `npm run build`, `npm run story`.
Node 22+.

For live AI stories, create `.env.local` in the project folder (get the key in our team chat, never commit it):

```
STORY_API_BASE=https://developer.amd.com.cn/radeon/api/v1
STORY_MODEL=Gemma-4-31B-IT
STORY_API_KEY=<key>
STORY_PROVIDER_LABEL="Gemma 4 31B on AMD Developer Cloud Token Factory (AMD GPUs)"
```
